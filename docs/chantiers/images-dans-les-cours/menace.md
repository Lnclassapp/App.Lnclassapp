# Menace — téléversement d'images de fiche et de question

> Exigée par `CLAUDE.md` (« Menace écrite d'abord » pour tout code qui lit un fichier envoyé). Écrite **après** le code de la PR, à partir de ce qu'il fait réellement : chaque parade cite `fichier:ligne`. Une menace sans parade dans le code est marquée **SANS PARADE** et n'est pas corrigée ici. Décision : [ADR-0105](../../decisions/adr/0105-images-des-fiches-et-des-questions.md), [UDR-0129](../../decisions/udr/0129-images-dans-l-editeur-de-fiche-la-question-et-la-lecture.md).

## Actifs

- Les élèves, qui ouvrent les fiches et les questions sur téléphone : leur navigateur ne doit exécuter aucun code venu d'un fichier, ni charger plus que prévu.
- La confidentialité des brouillons et du contenu non publié (une image suit la règle de lecture de sa fiche ou de son exercice).
- Le bucket et la base : pas de fichier arbitraire stocké, pas de ligne incohérente.
- La vie privée de l'auteur : pas de GPS ni d'appareil dans une image servie.

## Entrées non fiables

1. Le fichier envoyé : `POST /essential-images` et `POST /question-images` (`config/routes/teams.rb:69-70`), champs `essential_image[file]` et `question_image[file]` : octets, nom, type annoncé.
2. Le paramètre `essential` (slug) de l'envoi d'une image de fiche.
3. Le texte de remplacement (`alt`) et les `sgid` cités dans le texte riche de la fiche.
4. `public_id` dans l'URL de lecture (`config/routes/catalog.rb:8`, `config/routes/assessment.rb:10`).

## Sans parade dans le code de la PR

- **A. Taille de la requête avant lecture.** Le plafond de 300 Ko est contrôlé par le DTO (`article_image_input.rb:34`) après que Rack a reçu et écrit en fichier temporaire tout le corps. Aucune limite de taille de requête n'est posée dans l'application (`config/`, contrôleurs) ; ce qui existe devant elle (relais, hébergeur) n'est pas dans ce dépôt. Exposition : un compte `admin` ou `content` connecté, à 60 envois par minute. Parade à décider (limite au niveau du serveur ou du relais), non codée ici.
- **B. Décompression réelle.** Voir n° 7 : le flux compressé n'est pas vérifié contre la taille annoncée. Risque faible (le serveur ne décode jamais, le navigateur du lecteur est borné par l'en-tête à 1,44 Mpx, l'auteur est de l'équipe et authentifié), mais aucune parade n'existe.
- **C. Plafond à la création et images non rattachées.** Le plafond de 30 images ne s'applique qu'à une fiche **déjà enregistrée** (`upload_essential_image.rb:23-25`). À la création d'une fiche (pas de slug), le plafond est « tenu par l'éditeur » (commentaire de `upload_essential_image.rb`), c'est-à-dire par le JavaScript, donc contournable. Une image de question n'a aucun plafond de nombre. Seuls le débit (60 par minute) et la purge à 48 h bornent le volume.
